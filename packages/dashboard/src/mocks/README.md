# Mocks — designer mode infrastructure

Read-only [Mock Service Worker](https://mswjs.io/) handlers that let
designers iterate on the dashboard without a live emploke backend.
Enabled by `pnpm -F @emploke/dashboard dev:mock` (port 8788) or
`dev:mock:e2e` (port 5180, dedicated to the future
`emploke/designer` Playwright loop).

## Layout

```
mocks/
├── browser.ts            # Worker registration; consumed only via dynamic import
├── handlers.ts           # http.* handlers — one per fetch in src/api.ts
└── fixtures/
    ├── index.ts          # Barrel + artifactBodies map
    ├── workspaces.ts     # Workspace list (drives `/api/workspaces`)
    ├── agents.ts         # AgentEntry list
    ├── tasks.ts          # TaskRecord coverage matrix (#212)
    ├── sessions.ts
    ├── activities.ts     # Per-task activity timelines
    └── artifacts/        # Bodies served via /tasks/:tid/artifact/:name
        ├── sample.html
        ├── sample.json
        ├── sample.md
        ├── sample.png    # 1x1 transparent PNG
        └── sample.txt
```

## Adding a fixture

1. Add the data to the relevant file under `fixtures/`. Import types
   from `../../api/index.js` (not `@emploke/server`) — the dashboard's
   wire contract is canonical there.
2. If your route needs a new URL pattern, add the matching handler
   in `handlers.ts`. The catch-all at the bottom turns any unhandled
   `/api/*` mutation into a 501; unmatched GETs log a console warning
   via MSW's `onUnhandledRequest: "warn"` setting.
3. Restart `pnpm -F @emploke/dashboard dev:mock`.

## Production bundle

The `mocks/` subtree must never ship in prod. The dynamic import in
`src/main.tsx` (`if (import.meta.env.VITE_USE_MOCKS === "1") …`) is the
seam that lets vite tree-shake it out when the flag is unset. The
build-canary test in `packages/dashboard/test/no-mocks-in-prod-bundle.test.ts`
asserts the guarantee against the built `dist/` output.

## Mutations

POST/PATCH/DELETE are intentionally **mostly** not mocked — the only
exception is the `/schedules` surface (POST, PATCH, DELETE, POST
`/schedules/:id/run`) which is fully implemented to unblock the
dashboard schedule UI. Other mutation routes still hit the catch-all,
which returns HTTP 501 and logs the route to the browser console so
designers can see which surface a phase-2 implementation needs to
cover. Tracking: issue #213.

## Regenerating the service worker

`public/mockServiceWorker.js` is generated by `pnpm -F @emploke/dashboard
exec msw init public/ --save`. Re-run it after upgrading the `msw`
package to pull in fixes shipped in its SW source.
